## Fixture architecture

The accepted fixture constructors and projections are:

- exact-ID lookup for exactly one CTL-001 and exactly one HK-001;
- `canonicalSeedPlan`, which creates an isolated planned ledger and binds
  only CTL-001 complete;
- `seedPlan` for explicit CTL status seeds;
- `setIncompleteState` for explicit planned, ready, in-progress, and
  in-review projections;
- `bindCompletion` for schema-complete source-bound completion;
- `prepareTransition` and `rebindCompletion` for isolated transition and
  mutation fixtures;
- fail-closed item/protocol field classification and one shared local-reference
  extractor;
- a sorted, de-duplicated copy manifest with byte count and SHA-256.

Every source path is normalized, component-inspected, symlink-rejected, opened
with Linux `O_NOFOLLOW`, bound to the validated device/inode before reading,
and rechecked before and after the descriptor read. Sources must be regular
files and remain type, identity, size, modification-time, and digest stable.
Destinations remain below a physically resolved, process-user-owned private
`0700` temporary root. Destination files use no-follow, create-exclusive
descriptor opening at mode `0600`; parent/root identities, type, and copied
digest are rechecked. Cleanup accepts only the exact verified test-owned root.

## Deviations and residual risks

- GitHub pull-request verification executes GitHub's generated merge commit
  against accepted main, while the workflow metadata binds `headSha` to the
  exact implementation commit.
- Full local verification was unavailable without installing the unchanged
  dependency graph. Exact-head CI performed the install, tests, builds,
  release validation, fixtures, production audit, dependency review, and
  CodeQL checks.
- The production dependency audit is zero, but the unchanged full dependency
  graph still reports 16 high-severity findings in the installer/build
  toolchain. They are known build-chain risk and remain open for the separately
  planned packaging migration; this evidence does not conceal or resolve them.
- `O_NOFOLLOW`, FIFO testing, and the verified temporary-root behavior are
  Linux-specific. Cross-platform behavior requires separate controls.
- Descriptor binding and private-root containment substantially narrow
  replacement races. Pathname APIs cannot eliminate a malicious same-UID
  actor that can mutate the same private test tree; that actor is outside the
  accepted Stage A test-harness trust boundary.
- The verifier is agent-process separated, not organizationally independent.
- This evidence file cannot contain its own Git commit identity without a
  circular hash dependency. Its publication commit and exact-head checks are
  therefore bound by the PR head and subsequent verifier/owner records.

Generated output was semantically reviewed before publication. This evidence
contains no credential, token, private key, personal absolute checkout path, or
unrelated repository content.
